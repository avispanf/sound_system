M0 matrix
Existing: native serializable inspectors, source catalog/waveform, bank membership,
MusicTrack intro/body/layers/markers, MusicPlayer scheduling/transitions, global
parameter leases, bounded performance sampler and request history.
Missing: browser/document separation; stable document/subselection; bottom Deck;
shared audition session; embedded capture; offset/trim/move/seek timeline backend.
Current MusicLayer has no placement/trim fields. Legacy projection must be read-only
for time placement, retain native parameter curves and explicit property edits.

Implementation decisions
New reusable Event Editor shell; legacy menu/API routes remain compatible.
Versioned MusicArrangement asset and explicit legacy adapter; no automatic writes
on opening legacy documents. New player is opt-in; old MusicPlayer remains intact.
Times are seconds, musical grid is a projection through tempo/signature.
Timeline source trim is non-destructive. Runtime snapshots isolate authored edits.
Native Unity Mixer remains second window. No remote, Unreal or invented meters.

M1 implementation
Window/AudioMW/Event Editor and the Studio menu entry use the new shell.
Four independent browsers, per-browser search, pinned/preview documents, dirty
indicators, Save shortcut scoped to the window and native serializable Deck.
Container sources are actual project references. Source preview is explicitly dry.
Properties, Sources, Variation, Spatial, Bindings and Limits stay in the Deck.
Bank membership is explicit, Undoable and does not delete source assets.
Advanced tools and Inspector remain available; agent review is unchanged.

M2 implementation
MusicTrack has a cached read-only placement projection, real waveforms, seconds /
bars-beats, cues and grid. Curves remain native serialized fields. State profile
rules and current/pending/captured fade use the existing MusicPlayer backend.
Legacy conversion creates a separate arrangement; it never redirects gameplay.
Conversion caveat: arrangement parameter weights apply immediately, whereas the
legacy player smooths MusicLayer changes. Marker positions are copied as seconds.

M3 implementation
MusicArrangement version 1 stores stable lane/clip/cue identities and source refs.
ArrangementAuthoring provides Undoable add/move/duplicate/delete commands.
Timeline supports reference drop, drag placement, edge trim, session M/S, zoom,
scroll and Deck editing of routing, curves, fades and bounds. Tempo changes only
the grid. Clip time is seconds. Exit/loop bounds are explicit: clips outside the
playback interval do not extend it automatically. No time stretch is promised.
MusicArrangementPlayer is opt-in via its component/API, not a replacement for
MusicTrack or the existing music-state system. It snapshots on Play; authored
edits apply on restart. Seek cancels owned queued voices, reschedules from the
new position with 100 ms lead and applies source trim / loop modulo / fades.
Stop affects only that player. Four concurrent lanes are runtime-tested.

M4 implementation
Local Editor identity, pause/disconnected state, explicit global leases and
release are backed by the real runtime. Save does not promote overrides. An
explicit Save runtime value as default action is separate and Undoable.
The capture stores up to 600 timestamped samples at 10 Hz; records SFX physical /
virtual voices, capacity, requests/rejections/steals, AudioMW main-thread tick,
whole-frame main-thread timing and whole-frame GC. Missing recorders are NaN /
blank CSV, not zero. No DSP CPU, RMS/peak, LUFS or remote data is invented.
