AudioMW production workflow and UI review — 2026-11-17
Candidate: 0.5.0-preview.45

Scope
The latest request prioritizes FMOD-like dark authoring, indie/mobile/A scope,
minimum profiling/live editing and basic spatial processing. The existing guide
still governs native selection, pin/follow, dry/runtime separation, truthful data,
Undo and separate human-confirmed agent review. Unreal is not implemented here.

Implemented
- Dark neutral surfaces and shared green accents; waveform and selection agree.
- Native ObjectField/search/help icons retain square dimensions; source labels
  truncate rather than stretch their icons.
- Compact native properties retain field labels and aligned checkboxes.
- Music layer/rule and mixer binding drawers use native typed bindings; profile
  Inspectors refresh their binding state after Undo/Redo so subsequent edits do
  not replay stale serialized values. Crossfade retains its nonnegative input.
- Parameters/Spatial/Routing switch to a vertical library/detail split below
  620 points instead of clipping the right pane. Wide views retain three regions.
- Review Play Mode edits has stable rows, path tooltips, explicit Keep/Revert
  semantics, disabled actions when empty and wrapped footer text.
- Diagnostics footer now reserves enough height for wrapped status.
- Performance has bounded real-runtime capture and honest idle states; it has no
  fabricated DSP, live LUFS or remote-device measurements.
- Parameters separates read-only response preview from explicit live global control.
- Attenuation Inspector exposes optional distance filtering/spread and stereo pan;
  inactive curves remain authored but disabled. Spatial displays modeled values.

Visual/functional boundaries
This is an FMOD-inspired Unity workflow, not a pixel-identical FMOD editor. Native
Inspector chrome remains native. There is no invented event timeline, DSP deck,
bus meter or routing topology. Music without a state profile shows unavailable.
Direct reference equality is not claimed. Light theme was intentionally excluded.

Validation
See the candidate verification JSON and XML evidence for exact final counts.
The real BAD SHIFT production probe verifies live UI writes/restoration, asset
preservation, gameplay replacement preservation and actual profiler samples.
Desktop smoke is a separate generated macOS Mono Player, not a new gameplay build.
Listening, Android/iOS device budgets, Windows/Linux Players, IL2CPP and remote
Player live update remain open. Presets alone do not verify a platform.

Production priorities
Use shared profiles and current audits first. Next invest in device smoke CI,
representative large libraries, per-platform import/memory reports and safe bulk
changes with reviewable diffs. Avoid expensive acoustic simulation and pretending
all projects need the entire FMOD/Wwise feature set. See production-workflow.md.
